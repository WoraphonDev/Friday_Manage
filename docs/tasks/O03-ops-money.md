## ทำอะไร

- คิวกรณีผิดปกติ: เฉพาะรายการที่ระบบยืนยันเองไม่ได้ (A35a) · ผ่าน, ไม่ผ่าน (แจ้งลูกค้า), ผูกกับใบแจ้งหนี้อื่น, เก็บส่วนเกินเป็นเครดิต, ส่งเรื่องคืนเงิน
- รายการเงินเข้าพร้อม `verified_by` และผลกระทบยอดกับ statement
- ใบแจ้งหนี้: สร้างด้วยมือ (PO, หัก ณ ที่จ่าย), ยกเลิกแล้วออกใบลดหนี้, ส่งลิงก์จ่าย
- ค้างชำระ: ประวัติการเตือน, ติดต่อ, ขยายเวลา (หยุดเตือนและเลื่อนวันระงับ) · ขั้นตอนเตือนอัตโนมัติวันที่ 1, 3, 7 และระงับวันที่ 14
- ภาษี: e-Tax ที่ส่งไม่สำเร็จ, 50 ทวิ ที่รอรับ, สรุปภาษีขาย
- คืนเงิน / เครดิต / ใบลดหนี้ ตามวงเงิน · รายงานรายได้รายเดือนและปิดงวด · ส่งออกให้สำนักงานบัญชี

**Endpoint**
- **คิวกรณีผิดปกติ**:
  - `GET ops/payments/exceptions?reason`: ยอดที่ต้องได้ / ได้รับ, ลำดับเหตุการณ์ และสิ่งที่ระบบแนะนำ
  - `POST ops/payments/:id/{flag|confirm|reject|match|to-credit}`
  - ส่งคืนเงินใช้ `POST ops/refunds` พร้อม `paymentId`
- **รายการเงินเข้า**: `GET ops/payments/incoming?date` ส่ง `verifiedBy` และ `reconciliation` (`matched` = ผู้ให้บริการยืนยัน · `manual` = ทีมยืนยันจากสลิป · `pending`)
- **ใบแจ้งหนี้**: `GET ops/invoices`, `POST ops/invoices` (B1), `POST ops/invoices/:id/{void|send-link}` (B2, B5)
- **ค้างชำระ**: `GET ops/overdue` และ `POST ops/invoices/:id/{contact|extend}` (B3, B4) · งานเตือน `BillingService.runDunning` ทำทุกชั่วโมง (ปิดได้ด้วย `OPS_JOBS=off`)
- **ภาษี**: `GET ops/tax?month` (e-Tax ที่ต้องดู, 50 ทวิ ที่รอรับ, สรุปภาษีขาย) และ `POST ops/tax-documents/:id/retry`
- **คืนเงิน / เครดิต**: `GET ops/refunds`, `POST ops/refunds` (เกินวงเงินหรือชำระมาเกิน 30 วัน → 202) และ `POST ops/credits` (เกินวงเงิน → 202)
- **รายงาน**: `GET ops/revenue?months`, `POST ops/revenue/close` (แตะ key ซ้ำ) และ `GET ops/revenue/export?month&type=sales|credit_notes|wht` (B8 · CSV มี BOM · header `X-Report-Status: draft|closed`)

**คำตัดสินที่เลือกเอง**
- **ใบที่ทีมออกเอง** เก็บรายการสินค้า / ส่วนลด / หมายเหตุใน `audit_logs` `billing.checkout` (JSON แบบเดียวกับ API ลูกค้า) เพราะยังไม่มีตาราง invoice_items · ชำระแล้วต่ออายุแพ็กเกจตามช่อง `plan` · ชำระด้วยการโอนเท่านั้นจนกว่าจะมี Gateway
- **ผูกเงินเข้า (B7)** ได้เฉพาะใบใน Workspace เดียวกัน (FK `matched_invoice_id` เป็นแบบ tenant) · ยอดขาดจะไม่ปิดใบ เพราะยังไม่รองรับชำระบางส่วน
- **เตือนค้างชำระ**:
  - เกณฑ์วันที่ 1 / 3 / 7 / 14 นับจาก `due_date` · งานหยุดไปหลายวันจะส่งเฉพาะขั้นล่าสุด และบันทึกขั้นที่ข้ามเป็น `d1:skipped`
  - เลยกำหนดแล้ว subscription เป็น `past_due` · วันที่ 14 ระงับ Workspace

  - ยังไม่ทำ: ยกเลิกระงับเองเมื่อเงินเข้า (ปุ่มยกเลิกระงับอยู่ใน O02) และระงับแบบอ่านอย่างเดียว

## นำเข้า statement ธนาคาร (เฟส 2 · 23 พ.ย. 2569)

ผู้ใช้เลือกจาก storyboard: บัญชีรับเงินอยู่ **กสิกรไทย** · **ยังไม่เปิด Bill Payment** จึงทำนำเข้าเงินโอนธรรมดาก่อน

**หน้าจอ** (Ops › เงิน › กรณีชำระผิดปกติ)
- แท็บประวัติเงินเข้า: ปุ่ม "นำเข้า statement" (การเงิน) → วางไฟล์ → ดูผลจับคู่ → "บันทึก N รายการ · ส่ง M เข้าคิวต้องตรวจ"
- แท็บต้องตรวจ: การ์ด "เงินเข้าจาก statement ที่ยังจับคู่ไม่ได้" → ผูกใบแจ้งหนี้ (ยอดเกินเป็นเครดิต · ขาด = ใบยังค้าง) หรือ "ไม่เกี่ยวกับลูกค้า"
- ประวัติเงินเข้า: รายการที่ทีมยืนยันจากสลิปและพบใน statement แล้ว เปลี่ยนจาก "ตรวจจากสลิป" เป็น "ตรง"

**Endpoint** (การเงินทำรายการ · Owner / ผู้ตรวจดูได้)
- `GET ops/bank-statements` (บัญชีรับเงินจาก `BANK_*` + 5 รอบล่าสุด)
- `POST ops/bank-statements/preview` · `POST ops/bank-statements`: body = ไฟล์ตรง ๆ (`application/octet-stream` ≤ 5 MB · ชื่อไฟล์ใน `X-File-Name`)
- `GET ops/bank-statement-lines?status=review|matched|reconciled|ignored` (คิวต้องตรวจพร้อมใบค้างที่ยอดตรง)
- `POST ops/bank-statement-lines/:id/{match|ignore}` (เหตุผลบังคับ)

**อ่านไฟล์** (`payments/statement-parser.ts`): Excel (.xlsx) หรือ CSV แบบ UTF-8 / Windows-874 · หาแถวหัวตารางจากชื่อคอลัมน์ (วันที่ เวลา ฝากเงิน ถอนเงิน ยอดคงเหลือ ช่องทาง รายละเอียด / ชื่ออังกฤษ / คอลัมน์ยอดเดียว) · วันที่ ค.ศ. / พ.ศ. / ปี 2 หลัก / เดือนไทย · PDF ตอบให้ส่งออกเป็น Excel / CSV

**จับคู่** (ทีละรายการเงินเข้า เรียงตามเวลา · ใบ / รายการที่ใช้แล้วในไฟล์เดียวกันไม่ใช้ซ้ำ)
1. เลขใบแจ้งหนี้ในบันทึกช่วยจำ (เลขอ้างอิงที่ลูกค้าเห็นตอนโอน) · ยอดไม่ตรง = ต้องตรวจ · ใบชำระแล้ว = กระทบยอด หรือต้องตรวจ (อาจโอนซ้ำ)
2. สลิปรอตรวจที่ยอดเท่าใบแจ้งหนี้และเวลาโอนที่ลูกค้าแจ้งห่าง ≤ 2 วัน → ยืนยันสลิปแทนทีม (`verified_by = bank`) · สลิปที่ติดเหตุผิดปกติแล้วไม่แตะ
3. รายการที่ทีมยืนยันจากสลิปไปแล้ว ยอดตรง ห่าง ≤ 3 วัน → กระทบยอดอย่างเดียว
4. ใบค้างจ่าย (open) ที่ยอดตรงใบเดียว → สร้างรายการชำระ (`transfer` · `verified_by = bank`) แล้วปิดใบ · ตรงหลายใบ / ไม่พบ = ต้องตรวจ
- "ดอกเบี้ย" / interest = ไม่เกี่ยวกับลูกค้า · เงินออกไม่นำเข้า (นับในสรุป) · fingerprint (วันเวลา ยอด ยอดคงเหลือ รายละเอียด) กันนำเข้าซ้ำ
- ปิดใบด้วย `settleInvoice` เดิม: เปิดแพ็กเกจ · ใบกำกับภาษี / ใบเสร็จลงวันที่เงินเข้าใน statement · Audit log `ops.payment_statement` ต่อ Workspace และ `billing.statement_imported` ของพนักงาน

**ตาราง** (migration 0064 · เฉพาะ ops-api): `bank_statement_imports`, `bank_statement_lines`
