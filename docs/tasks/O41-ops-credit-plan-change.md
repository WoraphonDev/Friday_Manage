## ทำอะไร

- `packages/db/src/credit.ts`: `applyCredit(tx, invoice)` ใช้ในธุรกรรมเดียวกับการสร้างใบแจ้งหนี้ทุกทาง (ลูกค้าซื้อเอง, ทีมออก, ใบเพิ่มหนี้, ใบต่ออายุในอนาคต) · เขียน `workspace_credits` source `applied` (ติดลบ, ผูก invoice_id) · `invoices.credit_applied` · `amount_due` หักเครดิตแล้ว · เครดิตพอทั้งใบ → ชำระแล้วทันที ออกใบกำกับภาษีวันนั้น
- เครดิตไม่ใช่ส่วนลด: subtotal / VAT ไม่เปลี่ยน · ใบกำกับภาษีมีบรรทัด "ชำระด้วยเครดิต" ในส่วนวิธีชำระ (R4)
- ใบที่หักเครดิตถูกยกเลิก → คืนเครดิตเป็นแถว `reversal`
- C4 อัปเกรดกลางรอบ: บรรทัด "ชำระด้วยเครดิต" และยอดที่ต้องชำระจริง (R2) · ส่วนต่างติดลบ: ออกใบลดหนี้ส่วนที่ยังไม่ได้ใช้ แล้วเลือก "เข้าเครดิต" (ค่าเริ่มต้น) หรือ "คืนเงิน" (เกิน ฿10,000 ขออนุมัติ) (R3)
- แท็บการเงินของลูกค้าใน Ops: บัญชีเครดิต (ประวัติ, ลิงก์เอกสารต้นทาง, CSV) + สรุปใบถัดไป · "คืนเป็นเงิน" → ขั้นตอนคืนเงินเดิม (แถว `refunded`) (R1)
- ลูกค้า: การ์ดเครดิตคงเหลือ + ใบถัดไปในหน้า Billing · อัปเกรดเองคิดส่วนต่างตามวันที่เหลือ + หักส่วนที่จ่ายแล้ว + หักเครดิต → ไปหน้าชำระใบแจ้งหนี้เดิม (R5) · ลดแพ็กเกจเองมีผลรอบถัดไป (pendingPlanId) ตรวจขีดจำกัดล่วงหน้า วันที่มีผลยังเกิน → คงแพ็กเกจเดิม 1 รอบ + อีเมล Owner (R6) · แถบการเปลี่ยนที่รออยู่ + ยกเลิกได้ (R7)
- ย้ายสูตรส่วนต่างไปที่ใช้ร่วมระหว่าง ops-api และ API ลูกค้า

## บันทึกผล

**ใช้ร่วม** `packages/db/src/credit.ts`: `creditBalance` · `applyCreditToInvoice` (ops-api) · `reserveCredit` + `recordCreditUse` (checkout ของลูกค้าซึ่งแก้ใบหลังสร้างไม่ได้) · `reverseCreditOfInvoice` · `periodDays` / `prorateUpgrade` · `downgradeBlockers` (ขีดจำกัดจากเวอร์ชันสิทธิ์ที่มีผล + override ที่นั่ง)

**Migration 0046**: ให้ `friday_app` ใส่ `workspace_credits` ได้เฉพาะแถว `applied` ที่ติดลบ ผูกใบแจ้งหนี้ของ Workspace ตัวเอง (ลูกค้าสร้างเครดิตให้ตัวเองไม่ได้ · มี test)

**API ลูกค้า**
- `GET billing/quote` คืน `change` (new · upgrade + proration · next_cycle), `credit`, `payNowSatang`
- checkout: อัปเกรดกลางรอบคิดส่วนต่าง (ราคาใหม่ − ราคาเดิม) × วันที่เหลือ ÷ วันทั้งรอบ · รอบบิลเดิม · ใช้คูปองกับส่วนต่างไม่ได้ · หักเครดิตทุกใบ · เครดิตพอทั้งใบ → ชำระแล้วทันที เปิดแพ็กเกจ ออกใบกำกับภาษีเต็มยอด
- ลดแพ็กเกจ / เปลี่ยนรอบบิลระหว่างรอบที่จ่ายแล้ว → 409 `change_next_cycle` · `POST|DELETE billing/scheduled-change` (Owner / Admin) · `GET billing` มี `creditSatang` และ `pendingChange` พร้อม blockers

**ops-api**
- ออกใบแจ้งหนี้ (B1) และใบส่วนเพิ่มของใบเพิ่มหนี้หักเครดิตอัตโนมัติ · พอทั้งใบ = ชำระแล้วทันที (`settleInvoice`) และอีเมลบอกว่าชำระด้วยเครดิต · ยกเลิกใบที่ยังไม่ชำระคืนเครดิต (`reversal`)
- `GET ops/credits?workspaceId` (R1 · ทุกบทบาทที่เห็นลูกค้า) · `POST ops/credits:refund` (การเงิน · เกินวงเงินคืนเงินขออนุมัติ `billing.credit_refund`)
- C4: ตัวอย่างยอดมีเครดิตที่หักและยอดที่ต้องชำระ · เปลี่ยนรอบบิลกลางรอบ → ใบลดหนี้ส่วนที่ยังไม่ได้ใช้ (คิดจากยอดที่จ่ายจริง) + เครดิต แล้วใบใหม่หักเครดิต · ที่เหลือเข้าเครดิตหรือคืนเงิน (`remainder`)
- ลดแพ็กเกจที่ตั้งไว้: วันที่มีผลยังเกินขีดจำกัด → คงแพ็กเกจเดิมอีก 1 รอบ อีเมล Owner ครั้งเดียวต่อรอบ (คำตัดสินข้อ 2)
- ยอดที่คืน / ลดหนี้ได้ = เงิน + เครดิตที่ใช้ชำระใบนั้น

**เอกสาร**: ใบแจ้งหนี้มีบรรทัด "ชำระด้วยเครดิต" และยอดสุทธิ · ใบกำกับภาษีบอกช่องทาง / ยอดเครดิตในแถบรับชำระ · รายงานภาษีขายไม่นับใบที่ชำระด้วยเครดิตเป็นใบ ฿0

**หน้าเว็บ**: Ops แท็บการเงิน (บัญชีเครดิต + สรุป + คืนเป็นเงิน / เพิ่มเครดิต + CSV) · C4 บรรทัดเครดิตและตัวเลือกยอดที่เหลือ · ลูกค้า: หน้าชำระเงินแสดงส่วนต่าง / เครดิต / ตั้งลดแพ็กเกจ · หน้า Billing การ์ดเครดิตและแถบการเปลี่ยนที่รออยู่

**ตัดสินเอง / ต่างจากข้อเสนอ**
- ลูกค้าเปลี่ยนรอบบิลเองระหว่างรอบที่จ่ายแล้ว = มีผลรอบถัดไป (เหมือนลดแพ็กเกจ) เพราะการคืนส่วนที่ยังไม่ได้ใช้ต้องออกใบลดหนี้ซึ่งเป็นงานของทีมการเงิน · ทีมทำทันทีได้ผ่าน C4
- test เดิมที่ซื้อหลายครั้งใน Workspace เดียวกันจบรอบก่อนซื้อใหม่ (`endPeriod`) และล้างเครดิตที่ค้างจาก test ก่อนหน้า

**ยังรอ**: ใบต่ออายุอัตโนมัติ / ตัดบัตร (A35b) ใช้ `applyCreditToInvoice` ตอนสร้างใบ · คำถามนักบัญชี: ใบส่วนต่างเป็นใบใหม่ (แบบนี้) หรือใบเพิ่มหนี้
