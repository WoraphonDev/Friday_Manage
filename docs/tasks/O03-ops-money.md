## ทำอะไร

- คิวกรณีผิดปกติ: เฉพาะรายการที่ระบบยืนยันเองไม่ได้ (A35a) · ผ่าน, ไม่ผ่าน (แจ้งลูกค้า), ผูกกับใบแจ้งหนี้อื่น, เก็บส่วนเกินเป็นเครดิต, ส่งเรื่องคืนเงิน
- รายการเงินเข้าพร้อม `verified_by` และผลกระทบยอดกับ statement
- ใบแจ้งหนี้: สร้างด้วยมือ (PO, หัก ณ ที่จ่าย), ยกเลิกแล้วออกใบลดหนี้, ส่งลิงก์จ่าย
- ค้างชำระ: ประวัติการเตือน, ติดต่อ, ขยายเวลา (หยุดเตือนและเลื่อนวันระงับ) · ขั้นตอนเตือนอัตโนมัติวันที่ 1, 3, 7 และระงับวันที่ 14
- ภาษี: e-Tax ที่ส่งไม่สำเร็จ, 50 ทวิ ที่รอรับ, สรุปภาษีขาย
- คืนเงิน / เครดิต / ใบลดหนี้ ตามวงเงิน · รายงานรายได้รายเดือนและปิดงวด · ส่งออกให้สำนักงานบัญชี

**ส่งงาน 2026-11-09** · test `money.e2e.test.ts` 19 ข้อ · ops-api ทั้งชุด 65 ผ่าน · `pnpm typecheck` ที่รากผ่าน

**Endpoint**
- **คิวกรณีผิดปกติ**:
  - `GET ops/payments/exceptions?reason`: ยอดที่ต้องได้ / ได้รับ, ลำดับเหตุการณ์ และสิ่งที่ระบบแนะนำ
  - `POST ops/payments/:id/{flag|confirm|reject|match|to-credit}`
  - ส่งคืนเงินใช้ `POST ops/refunds` พร้อม `paymentId`
- **รายการเงินเข้า**: `GET ops/payments/incoming?date` ส่ง `verifiedBy` และ `reconciliation` (`matched` = ผู้ให้บริการยืนยัน · `manual` = ทีมยืนยันจากสลิป · `pending`)
- **ใบแจ้งหนี้**: `GET ops/invoices`, `POST ops/invoices` (B1), `POST ops/invoices/:id/{void|send-link}` (B2, B5)
- **ค้างชำระ**: `GET ops/overdue` และ `POST ops/invoices/:id/{contact|extend}` (B3, B4) · งานเตือน `BillingService.runDunning` ทำทุกชั่วโมง (ปิดได้ด้วย `OPS_JOBS=off`)
- **ภาษี**: `GET ops/tax?month` (e-Tax ที่ต้องดู, 50 ทวิ ที่รอรับ, สรุปภาษีขาย) และ `POST ops/tax-documents/:id/retry`
- **คืนเงิน / เครดิต**: `GET ops/refunds`, `POST ops/refunds` (เกินวงเงินหรือชำระมาเกิน 30 วัน → 202) และ `POST ops/credits` (เกินวงเงิน → 202)
- **รายงาน**: `GET ops/revenue?months`, `POST ops/revenue/close` (แตะ key ซ้ำ) และ `GET ops/revenue/export?month&type=sales|credit_notes|wht` (B8 · CSV มี BOM · header `X-Report-Status: draft|closed`)

**คำตัดสินที่เลือกเอง**
- **ใบที่ทีมออกเอง** เก็บรายการสินค้า / ส่วนลด / หมายเหตุใน `audit_logs` `billing.checkout` (JSON แบบเดียวกับ API ลูกค้า) เพราะยังไม่มีตาราง invoice_items · ชำระแล้วต่ออายุแพ็กเกจตามช่อง `plan` · ชำระด้วยการโอนเท่านั้นจนกว่าจะมี Gateway
- **ผูกเงินเข้า (B7)** ได้เฉพาะใบใน Workspace เดียวกัน (FK `matched_invoice_id` เป็นแบบ tenant) · ยอดขาดจะไม่ปิดใบ เพราะยังไม่รองรับชำระบางส่วน
- **เตือนค้างชำระ**:
  - เกณฑ์วันที่ 1 / 3 / 7 / 14 นับจาก `due_date` · งานหยุดไปหลายวันจะส่งเฉพาะขั้นล่าสุด และบันทึกขั้นที่ข้ามเป็น `d1:skipped`
  - เลยกำหนดแล้ว subscription เป็น `past_due` · วันที่ 14 ระงับ Workspace
  - ขยายเวลา = เลื่อน `due_date` จึงหยุดเตือนและเลื่อนวันระงับไปเอง (ไม่เกิน 30 วันจากวันเดิม)
  - ใบที่แนบสลิปรอตรวจไม่นับเป็นค้าง
  - ยังไม่ทำ: ยกเลิกระงับเองเมื่อเงินเข้า (ปุ่มยกเลิกระงับอยู่ใน O02) และระงับแบบอ่านอย่างเดียว
- **ติดต่อทาง LINE (B3)**: หลังบ้านยังส่ง LINE ไม่ได้ จึงบันทึกเป็นประวัติ · อีเมลส่งจริง
- **ส่งลิงก์จ่าย (B5)**: ลิงก์ไปหน้าเรียกเก็บเงินของลูกค้า `/work/{slug}/billing?invoice=` · ส่งได้เฉพาะผู้ติดต่อเรื่องเงินของลูกค้า · QR / บัตรใหม่รอ A35b
- **ใบลดหนี้**: เลข `CN-YYMM-NNNN` ต่อเนื่องทั้งระบบ · แยกก่อน VAT / VAT ตามสัดส่วนของใบเดิม · ยกเลิกใบที่ชำระแล้วไม่เปลี่ยนแพ็กเกจ
  - ยังไม่ส่ง e-Tax ของใบลดหนี้ (รอผู้ให้บริการ e-Tax)
  - การโอนคืนจริงทีมการเงินทำเองจนกว่าจะมี Gateway (`refund_method` บันทึกช่องทาง)
- **ปิดงวด** บันทึกใน `staff_audit_logs` (`billing.period_closed`) เพราะไม่มีตารางแยก · ใบแจ้งหนี้ / ใบลดหนี้ลงวันที่วันนี้เสมอ จึงไม่มีรายการย้อนเข้างวดที่ปิด · สร้างใบในเดือนที่ปิดแล้วตอบ 409
- **รายงานรายได้**: รับรู้ตามจำนวนเดือนของรอบ (รายปีกระจาย 12 เดือน) · ค่าธรรมเนียมใช้ `cost_rates` (ตั้งใน B9 ของ O06)

**ยังไม่ทำ**
- ส่งรายงานถึงสำนักงานบัญชีอัตโนมัติทุกวันที่ 5 (ยังไม่มีที่ตั้งอีเมลสำนักงานบัญชี)
- ขอ 50 ทวิ อัตโนมัติวันที่ 7 / 30
- e-Withholding Tax
- นำเข้า statement ธนาคาร (เฟส 2)
- ใช้เครดิตหักใบแจ้งหนี้รอบถัดไป (ต้องทำที่ checkout ของ API ลูกค้า → W22 / A35b)
