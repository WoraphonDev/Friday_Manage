# 06 · บทบาทพนักงานใน Friday Ops

**สถานะ:** ร่างแรก (9 พ.ย. 2569) · หน้าจอ "8 · พนักงาน สิทธิ์ และ Audit log", A1, A2, A12, G7, G8, G12 ใน [Canvas Friday Ops](https://claude.ai/artifact/Q8tsmLfQqS1aUJ2rNrkw9r) · คำตัดสินอยู่ใน [decisions.md](../decisions.md) › "Friday Ops: บทบาทพนักงาน"

ใช้กับพนักงานทีม Friday ใน `apps/ops-api` และ `apps/ops-web` เท่านั้น · บทบาทของผู้ใช้ฝั่งลูกค้าอยู่ใน [04-permissions.md](04-permissions.md)

## 1. แยก 4 เรื่องออกจากกัน

| เรื่อง | ใช้ทำอะไร | ให้สิทธิ์ |
|---|---|---|
| **บทบาท** | กำหนดว่าเห็นและทำอะไรได้ · 1 คนมีได้หลายบทบาท | ✅ |
| **วงเงิน** | ทำเองได้ถึงเท่าไร ต่อคน | ✅ |
| **แผนก** | โครงสร้างองค์กร ใช้แสดงผล รายงาน และ Audit log | ❌ |
| **ทีม Support** | แจกงาน Ticket และส่งแจ้งเตือน (หน้า "ตั้งค่าการแจกงาน") | ❌ |

## 2. บทบาท

| บทบาท | key | เห็น / ทำได้ | ไม่เห็น |
|---|---|---|---|
| Owner | `owner` | อนุมัติคำขอของคนอื่นทุกเรื่อง ไม่จำกัดวงเงิน · จัดการพนักงาน บทบาท วงเงิน ตั้งค่า · ดูทุกหน้า | — |
| การเงิน | `finance` | คิวชำระ ใบแจ้งหนี้ ภาษี คืนเงิน ส่วนลด เปลี่ยนแพ็กเกจ (ตามวงเงิน) · ระงับเพราะค้างชำระตามนโยบาย · รายงาน | ข้อความใน Ticket |
| Support | `support` | Ticket ผู้ใช้ เข้าบัญชีลูกค้าแบบอ่านอย่างเดียว ขยายทดลองใช้ (ตามวงเงิน) | ยอดเงินรายลูกค้า (เห็นแค่สถานะจ่ายแล้ว / ค้าง) |
| วิศวกร | `engineer` | สถานะระบบ เหตุขัดข้อง ปิดปรับปรุง งานที่ล้ม ประวัติการส่ง Feature flags | ข้อมูลเงิน · อีเมลลูกค้า (เห็นรหัสและชื่อ Workspace) |
| ผู้ตรวจ | `auditor` | อ่านรายงานการเงินและ Audit log · ส่งออกได้ · ใช้กับสำนักงานบัญชีภายนอก มีวันหมดอายุ | แก้ไขอะไรไม่ได้ |

**Owner ไม่ได้ผ่านทุกอย่างอัตโนมัติ:** Owner อนุมัติได้ทุกเรื่อง แต่จะทำงานการเงินหรือ Support เองต้องมีบทบาทนั้นด้วย (ทีมเล็กใส่ไว้ตั้งแต่แรก) · เปิดบทบาทอื่นชั่วคราวใช้สิทธิ์ฉุกเฉิน (ข้อ 5) · ตารางสิทธิ์รายการอยู่ในหน้าจอ "8"

## 3. วงเงินเริ่มต้น

| เรื่อง | ทำเองได้ | เกินต้องให้ Owner อนุมัติ |
|---|---|---|
| คืนเงิน | ≤ ฿10,000 | > ฿10,000 หรือเกิน 30 วันหลังชำระ |
| ให้เครดิต | ≤ ฿5,000 | > ฿5,000 |
| ส่วนลด / คูปองเฉพาะราย | ≤ 30% และ ≤ 12 รอบ | เกินข้อใดข้อหนึ่ง |
| ขยายทดลองใช้ | รวม ≤ 30 วัน และ ≤ 2 ครั้ง | เกิน |
| ปรับสิทธิ์เฉพาะราย | เกินแพ็กเกจ ≤ 20% และมีวันหมดอายุ | เกิน หรือไม่มีวันหมดอายุ |
| ลบข้อมูลตามคำขอ PDPA · ปิดปรับปรุงทั้งระบบ · โอนความเป็นเจ้าของ · ระงับ Workspace ที่จ่ายเงิน (ยกเว้นค้างชำระตามนโยบาย) | — | ทุกครั้ง |

Owner ปรับวงเงินรายคนได้ · คำขออนุมัติหมดอายุตามหน้าคืนเงินและอนุมัติ (24 ชม.–7 วัน)

## 4. การอนุมัติ

- ผู้ขออนุมัติรายการของตัวเองไม่ได้ (ยกเว้นข้อถัดไป)
- **ช่วงที่มี Owner คนเดียว** (นับเฉพาะบัญชีที่ใช้งานอยู่): คำขอที่ Owner ทำเองและเกินวงเงิน อนุมัติตัวเองได้ (G12)
  - ต้องใส่เหตุผลและแตะ Security key
  - Audit log ติดป้าย `self_approved` · กรองดูได้
  - ส่งสรุปรายวันถึงอีเมลส่วนตัวของ Owner
  - หน้าพนักงานแสดงแถบเตือนตลอด
  - ปิดเองทันทีเมื่อมี Owner คนที่สอง
- **ใช้อนุมัติตัวเองไม่ได้เลย:** เข้าบัญชีลูกค้าโหมดแก้ไข และลบข้อมูลตามคำขอ PDPA · ช่วงมี Owner คนเดียวจึง**ไม่เปิดโหมดแก้ไข** (C1 แสดง "ยังไม่เปิด") และคง constraint `support_sessions_write_approval` ไว้ตามเดิม

## 5. สิทธิ์ฉุกเฉิน (break-glass)

Owner เปิดบทบาทที่ไม่มีให้ตัวเองได้ 30 นาทีหรือ 1 ชม. (A12) · ต้องใส่เหตุผลและแตะกุญแจ · แสดงแถบสีแดงตลอดเวลาที่เปิด · ลง Audit log และแจ้งอีเมลส่วนตัวของ Owner และผู้ตรวจ

## 6. ข้อมูล

แก้ `staff_users` (หมวด N ใน [01-entities.md](01-entities.md)):

| ฟิลด์ | เดิม | ใหม่ |
|---|---|---|
| `role` text | `admin` · `finance` · `support` | ลบ · แทนด้วย `roles` |
| `roles` text[] | — | `owner` · `finance` · `support` · `engineer` · `auditor` · ต้องมีอย่างน้อย 1 |
| `department` text | — | ป้ายชื่อ ไม่มีผลกับสิทธิ์ |
| `limits` jsonb | — | `{ refund_satang, credit_satang, discount_pct, discount_cycles, trial_days, trial_times }` · null = ใช้ค่าเริ่มต้น |
| `status` | — | `invited` · `active` · `suspended` · `disabled` |
| `expires_at` tstz | — | ใช้กับผู้ตรวจภายนอก |

ตารางใหม่ `staff_elevations` (สิทธิ์ฉุกเฉิน): staff_id, role, reason, started_at, ends_at, ended_by

**ย้ายข้อมูลเดิม:** `admin` → `{owner}` · `finance` → `{finance}` · `support` → `{support}`

## 7. ผลกับโค้ด

- `apps/ops-api/src/auth/auth.guard.ts`: `Staff.role` → `roles[]` · `@Roles(...)` ผ่านเมื่อมีบทบาทใดบทบาทหนึ่ง · **เลิกให้ `admin` ผ่านทุกอย่าง** · นับบทบาทจากสิทธิ์ฉุกเฉินที่ยังไม่หมดเวลาด้วย
- เพิ่ม `@Approval(kind)` ตรวจวงเงินของผู้ทำ ถ้าเกินสร้างคำขออนุมัติแทนการทำรายการ
- Audit log ของทีม Friday บันทึก `roles` ตอนทำรายการ, `approved_by` และ `self_approved`
- `ops-web` ซ่อนเมนูตามบทบาท (ไม่ใช่ตามบทบาทเดียวแบบเดิม)
