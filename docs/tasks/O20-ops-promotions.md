## ทำอะไร

- แก้ราคา / ขีดจำกัดของแพ็กเกจ (P1) · มีผลกับลูกค้าใหม่ทันที ลูกค้าเดิมคงราคาเดิมจนกว่าจะเลือกย้าย (grandfathering) · ทุกการแก้เก็บเป็นเวอร์ชัน
- คูปอง: ส่วนลด % / จำนวนเงิน / ใช้ฟรี N เดือน · ระยะเวลา (N รอบบิลแรก / ครั้งเดียว / ตลอดไป) · แพ็กเกจที่ใช้ได้ · จำนวนสิทธิ์ · วันหมดอายุ · เฉพาะลูกค้าใหม่ · ใช้คู่กับคูปองอื่น · ร่าง / เปิด / ปิด (P4)
- ลูกค้ากรอกโค้ดในหน้าชำระเงิน (W22) · รายงาน "ลูกค้าที่จ่ายต่อหลังหมดส่วนลด"
- แก้ราคาและเปิดคูปองต้องแตะ key (G4) · Audit ทุกครั้ง

ราคาแบบมีเวอร์ชัน (P1)
- ทุกการบันทึก = เวอร์ชันใหม่ · แก้ชื่อ / แสดงในหน้าราคา / เปิดรับสมัครใหม่ มีผลทันที · เปลี่ยนราคาต้องมีคนอนุมัติเสมอ (`promotions.plan_price` · ช่วง Owner คนเดียวอนุมัติตัวเองได้ตามกติกาเดิม) · ทุกครั้งต้องแตะ key (G4) และใส่เหตุผล · Audit ใน staff_audit_logs
- ลูกค้าเดิม (active / past_due ที่ต่ออายุแพ็กเกจเดิม) ผูกกับเวอร์ชันที่จ่ายล่าสุด · ย้ายแพ็กเกจเอง = ราคาปัจจุบัน · ลูกค้าใหม่ / ทดลองใช้ = ราคาปัจจุบัน · ลดราคาแล้วลูกค้าเดิมได้ราคาที่ถูกกว่าเสมอ
- "ลูกค้าเดิมเปลี่ยนตามรอบถัดไป": ลูกค้าเดิมย้ายราคาในใบแจ้งหนี้ที่ออกตั้งแต่ 30 วันหลังอนุมัติ · อนุมัติแล้วส่งประกาศ (อีเมล + แบนเนอร์ ผ่าน `AnnouncementsService` ของ O24) ถึง Owner / Admin ของลูกค้าที่จ่ายแพ็กเกจนั้นอยู่ให้อัตโนมัติ
- Free / Enterprise แก้ราคาไม่ได้ (฿0 / ตามใบเสนอราคา) · ปิดรับสมัครใหม่แล้วลูกค้าใหม่ได้ 422 `plan_not_open` ลูกค้าเดิมต่ออายุได้

คูปอง (P4)
- ส่วนลด % / จำนวนเงินต่อรอบ / ใช้ฟรี N เดือน · ครั้งเดียว / N รอบบิลแรก / ตลอดไป · แพ็กเกจที่ใช้ได้ · จำนวนสิทธิ์ · วันหมดอายุ (สิ้นวันเวลาไทย) · เฉพาะลูกค้าใหม่ (ยังไม่เคยชำระใบที่มียอด) · ใช้คู่กับคูปองอื่น · ร่าง / เปิด / ปิด
- เปิดใช้ต้องแตะ key (ตรวจก่อนบันทึก เพื่อให้หน้าเว็บส่งคำขอเดิมซ้ำหลังแตะได้) · เกินวงเงินส่วนลดของพนักงาน (06 › 3: ≤ 30% และ ≤ 12 รอบ) → คำขออนุมัติ `promotions.coupon_activate` · ตลอดไป และใช้ฟรี N เดือน (= ลด 100%) ต้องอนุมัติเสมอเมื่อใช้วงเงินเริ่มต้น · จำนวนเงินเทียบเป็น % ของราคารายเดือนที่ถูกที่สุดในแพ็กเกจที่ใช้ได้
- เปิดแล้วแก้ได้เฉพาะคำอธิบาย / วันหมดอายุ / จำนวนสิทธิ์ (เงื่อนไขอื่น = คัดลอกเป็นคูปองใหม่) · ปิดก่อนกำหนดต้องมีเหตุผล คนที่ใช้แล้วยังได้ส่วนลดครบรอบ · เปิดกลับได้
- นับสิทธิ์ = Workspace ที่ใช้แล้ว + ที่ใส่โค้ดแล้วมีใบแจ้งหนี้รอชำระ · checkout ที่ใช้โค้ดเดียวกันพร้อมกันต่อคิวด้วย advisory lock
- 1 Workspace ใช้คูปองเดียวกันได้ครั้งเดียว · รอบนับเมื่อชำระ (ใบที่ไม่ได้จ่ายไม่กินรอบ) · ส่วนลดหลายรอบได้ต่อเองโดยไม่ต้องใส่โค้ดอีก (เฉพาะแพ็กเกจที่คูปองใช้ได้) · ซ้อนกันได้เฉพาะเมื่อทุกใบติด "ใช้คู่กับคูปองอื่นได้" (หักตามลำดับ รวมไม่เกินราคา)
- รายงาน "ลูกค้าที่จ่ายต่อหลังหมดส่วนลด" ต่อคูปอง: นับเฉพาะคนที่ใช้ครบรอบแล้ว (ตลอดไปไม่มีวันหมด) และรอบสุดท้ายที่ได้ส่วนลดจบแล้ว · จ่ายต่อ = มีใบที่ชำระและมียอดออกหลังใบสุดท้ายที่ได้ส่วนลด · ยังไม่มีใครครบ = "—" · ดูรายคนได้ใน "ดูลูกค้าที่ใช้"
- หัวตาราง: คูปองที่ใช้งานอยู่ และส่วนลดที่ให้ไปเดือนนี้ (ใบที่ชำระในเดือนปัจจุบันเวลาไทย)

API ลูกค้า (W22)
- `GET w/{ws}/billing/quote?coupon=` เพิ่ม `listPrice`, `discount`, `discounts[]`, `coupon`, `freeMonths`, `grandfathered` · โค้ดใช้ไม่ได้ตอบ 422 `coupon_not_found` / `coupon_inactive` / `coupon_expired` / `coupon_plan_mismatch` / `coupon_exhausted` / `coupon_new_customers_only` / `coupon_already_used` / `coupon_not_stackable` พร้อมข้อความไทย · ไม่สนตัวพิมพ์เล็ก / ใหญ่
- `POST billing/checkout` รับ `coupon` · VAT / หัก ณ ที่จ่าย คิดจากยอดหลังส่วนลด · ใบที่ยอด 0 (ใช้ฟรี N เดือน / ลด 100%) ปิดเป็น paid ทันทีโดยไม่ผ่านผู้ให้บริการ (`payment: null, free: true`) และไม่ออกใบกำกับภาษี / ใบเสร็จเพราะไม่มีการรับเงิน · ใช้ฟรี N เดือนใบแรกครอบคลุม N เดือน แล้วรอบถัดไปจ่ายตามรอบที่เลือก
- ใบแจ้งหนี้ทุกที่มี `discount` · PDF แสดงราคาแพ็กเกจเต็มแล้วหักส่วนลดเป็นอีกบรรทัด · MRR (A34) = ยอดหลังส่วนลด
- `GET public/plans` ใช้ชื่อที่แสดง และมี `listed` / `openForSignup` · หน้าราคาซ่อนแพ็กเกจที่ไม่แสดง · OpenAPI อัปเดตแล้ว

**สิ่งที่ A35b ต้องทำเรื่องคูปอง: ไม่มีเพิ่ม** นอกจากตัดเงินตาม `amount` ใน `GatewayRequest` (= `invoice.amount_due` หลังหักส่วนลดแล้ว) เหมือนเดิม · ไม่ต้องสร้างคูปอง / Promotion code ในระบบของผู้ให้บริการ (ถ้าเลือก Stripe ห้ามใช้ Stripe Coupons ซ้อนอีกชั้น ไม่อย่างนั้นจะหักซ้ำ) · ใบยอด 0 ไม่ถูกส่งไปผู้ให้บริการ · ตัดบัตรอัตโนมัติตามรอบ (A35b) ต้องสร้างใบแจ้งหนี้ผ่านเส้นทางเดียวกับ checkout (`BillingService.price`) เพื่อให้ได้ส่วนลดที่ได้ต่อและราคา grandfathered · Webhook / กระทบยอดเดิมเรียก `commitCouponUses` แล้ว

ต่างจาก Canvas
- การ์ดแพ็กเกจไม่มีป้าย "นิยมสุด" (ไม่มีข้อมูลนี้) · แสดงป้าย "ไม่แสดงในหน้าราคา" / "ปิดรับสมัครใหม่" และ "ราคาเดิม N ราย" แทน
- การ์ดแคมเปญ (ขยายทดลองอัตโนมัติ / Referral / ชวนกลับ) ไม่อยู่ในงานนี้ · แท็บ "แคมเปญ" แสดงสถานะว่าง
- แท็บ "ประกาศถึงลูกค้า" ฝังประวัติประกาศของ O24 (ไม่สร้างใหม่) · หน้า `/announcements` เดิมยังอยู่ · การเงินที่ไม่ใช่ Owner เห็นข้อความว่าเฉพาะ Owner
- แท็บ "ประวัติราคา" เป็นตาราง (Canvas มีแค่ชื่อแท็บ)
- P1: ตัวเลือก "เมื่อเปลี่ยนราคา" กดได้เมื่อแก้ราคา · ราคาปีเว้นว่าง = ราคาเดือน × 10 · เพิ่มช่องเหตุผล (บังคับ เพราะลง Audit และเป็นเวอร์ชัน)
- Drawer คูปองเพิ่มช่อง "จำนวนรอบบิล" · ใช้ฟรี N เดือนบังคับ "ครั้งเดียว" และปิด "ใช้คู่กับคูปองอื่นได้" · ตารางคูปองแสดง "รอชำระ N" และป้าย "รออนุมัติ"
- P4 เป็นเมนูที่มีรายการเพิ่ม "แก้ไขร่าง" และ "เปิดใช้คูปอง"
- หน้าชำระเงิน: ป้าย "ใช้โค้ดแล้ว" แทนช่องโค้ดขณะใช้โค้ดอยู่ (Canvas แสดงทั้งสองพร้อมกัน) · ส่วนลดที่ได้ต่อและใช้ฟรี N เดือนไม่มีใน Canvas ใช้รูปแบบบรรทัดเดียวกัน
- ตรวจกับ markup ของ Canvas และ component test · ยังไม่ได้ถ่ายภาพเทียบใน browser ที่ 1440 / 390 px
