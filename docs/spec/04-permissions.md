# 04 · สิทธิ์ของแต่ละ Role

ถอดจากหน้า H (Workspace Members), 7 (Members), L2 (Project Settings › สิทธิ์ของแต่ละ Role), M1 (403 / Viewer) และคำตัดสินเรื่อง Guest · ชื่อสิทธิ์ตรงกับคอลัมน์ "สิทธิ์" ใน [03-api.md](03-api.md)

## 1. Role มี 2 ชั้น

| ชั้น | Role | ตั้งที่ |
|---|---|---|
| Workspace | **Owner** · **Admin** · **Member** · **Guest** | H · `workspace_member.role` |
| โปรเจกต์ | **Admin** · **Member** · **Viewer** (+ Project Owner อีก 1 คน) | 7, L2 · `project_member.role` · Project Owner = `project.owner_user_id` |

- Guest คือคนนอกองค์กร เช่น ลูกค้า **ไม่นับ Seat** และไม่เห็นรายชื่อคนในองค์กร
- คนหนึ่งมี Role ต่างกันได้ในแต่ละ Workspace (Owner ที่หนึ่ง เป็น Guest อีกที่ได้) และต่างกันในแต่ละโปรเจกต์

## 2. สิทธิ์ระดับ Workspace

ไม่ปรับรายคน · ตายตัวตาม Role

| สิทธิ์ | ทำอะไรได้ | Owner | Admin | Member | Guest |
|---|---|:-:|:-:|:-:|:-:|
| `ws.view` | เข้า Workspace, Home, My Tasks, Inbox, ค้นหา | ✓ | ✓ | ✓ | ✓ |
| `ws.directory.view` | เห็นรายชื่อสมาชิกทั้งองค์กร (H) | ✓ | ✓ | ✓ | — |
| `ws.project.create` | สร้างโปรเจกต์, นำเข้า Excel เป็นโปรเจกต์ใหม่ | ✓ | ✓ | ✓ | — |
| `ws.members.manage` | เชิญ, เปลี่ยน Role, ปิดการใช้งาน, ลิงก์เชิญ, อนุมัติคำขอเข้าร่วม | ✓ | ✓ | — | — |
| `ws.settings` | Admin Console: วันหยุด, เวลาทำงาน, Template, ทีม, ช่องทางแจ้งเตือน, Integration, ความปลอดภัย, API token | ✓ | ✓ | — | — |
| `ws.audit.view` | Audit log และ Export CSV | ✓ | ✓ | — | — |
| `ws.workload.view` | Workload รวมทุกโปรเจกต์ (N1) | ✓ | ✓ | — | — |
| `ws.billing` | แพ็กเกจ, ชำระเงิน, ใบกำกับภาษี, 50 ทวิ | ✓ | ✓ | — | — |
| `ws.owner` | ลบ Workspace, โอนความเป็น Owner, ยกเลิกแพ็กเกจ, กู้คืนโปรเจกต์ที่ลบ, เปิดสิทธิ์ให้ทีม Friday แบบแก้ไขได้ | ✓ | — | — | — |

กติกาเพิ่มเติม:
- Workspace ต้องมี Owner อย่างน้อย 1 คนเสมอ · Admin เปลี่ยน Role ของ Owner ไม่ได้
- Admin ตั้งคนอื่นเป็น Admin ได้ แต่ตั้งเป็น Owner ไม่ได้
- เชิญ Guest ไม่ใช้ Seat · เปลี่ยน Guest เป็น Member ต้องมี Seat ว่าง (ไม่มี → 402)

## 3. สิทธิ์ระดับโปรเจกต์

### 3.1 ตารางที่ปรับได้รายโปรเจกต์ (หน้า L2)

10 แถวตามหน้าจอ · คอลัมน์ Admin เปิดทุกอย่างเสมอ (ปิดไม่ได้) · Member และ Viewer เปิดปิดได้ทุกแถว · ค่าที่ต่างจากค่าเริ่มต้นเก็บใน `project_role_permission`

| แถวในหน้า L2 | สิทธิ์ | Admin | Member | Viewer |
|---|---|:-:|:-:|:-:|
| ดูทุก tab และงาน | `project.view` | ✓ | ✓ | ✓ |
| คอมเมนต์ | `issue.comment` | ✓ | ✓ | ✓ |
| สร้างและแก้ไขงาน | `issue.create` + `issue.edit` | ✓ | ✓ | — |
| ลบงาน | `issue.delete` | ✓ | — | — |
| **เปลี่ยน Due โดยไม่ต้องขออนุมัติ** | `issue.change_due_directly` | ✓ | — · **PM เปิดได้** | — |
| อนุมัติคำขอเลื่อน Due | `due_request.approve` | ✓ | — | — |
| อัปโหลด / ลบไฟล์ | `file.upload` + `file.delete` | ✓ | ✓ | — |
| จัดการ Sprint (Start / Complete) | `sprint.manage` | ✓ | — | — |
| เชิญสมาชิกเข้าโปรเจกต์ | `project.invite` | ✓ | — | — |
| แก้ Project Settings | `project.settings` | ✓ | — | — |

✓ = ค่าเริ่มต้นเปิด · — = ค่าเริ่มต้นปิด · การเปิดปิดทุกช่องบันทึกใน Audit log (หมวด perm)

กติกาการเปลี่ยน Due ละเอียดอยู่ที่ [03-api.md › กติกาการเปลี่ยน Due](03-api.md#กติกาการเปลี่ยน-due)

### 3.2 สิทธิ์ที่ตายตัวตาม Role (ไม่อยู่ในหน้า L2)

| สิทธิ์ | ทำอะไรได้ | Admin | Member | Viewer |
|---|---|:-:|:-:|:-:|
| `project.workload.view` | Workload, Lead Dashboard, Risk | ✓ | ✓ | ✓ (ยกเว้น Guest) |
| `project.reports.view` | Reports, Traceability, การแก้ไขแผน | ✓ | ✓ | ✓ (ยกเว้น Guest) |
| `issue.record_test` | บันทึกผลทดสอบ | ✓ | ✓ | — |
| `issue.time_log` | บันทึกเวลา (เมื่อโปรเจกต์เปิด Time log) | ✓ | ✓ | — |
| `due_request.create` | ขอเลื่อน Due | ✓ | ✓ เมื่อมี `issue.edit` แต่ไม่มี `issue.change_due_directly` | — |
| `project.baseline` | ตั้ง Baseline, Import อัปเดตแผน | ✓ | — | — |
| `project.automation` | สร้าง / แก้ Automation | ✓ | — | — |
| `project.views.share` | บันทึก View ให้ทั้งโปรเจกต์เห็น | ✓ | — | — |
| `project.trash` | ดูและกู้คืนงาน / ไฟล์ในถังขยะ | ✓ | — | — |
| `project.archive` | Archive / Restore โปรเจกต์ | ✓ | — | — |
| `project.owner` | โอนความเป็นเจ้าของ, ลบโปรเจกต์ | Project Owner เท่านั้น | | |

### 3.3 สิทธิ์ตามความเป็นเจ้าของ

ไม่ขึ้นกับ Role ใช้ร่วมกับสิทธิ์ด้านบน

| เรื่อง | กติกา |
|---|---|
| คอมเมนต์ | แก้ / ลบได้เฉพาะของตัวเอง · Admin ลบของคนอื่นได้ (ซ่อนข้อความ เหลือ "ถูกลบโดย Admin") |
| คำขอเลื่อน Due | ผู้ขอยกเลิกของตัวเองได้ · อนุมัติคำขอของตัวเองไม่ได้ แม้เป็น Admin (ต้องให้ Admin คนอื่น หรือแก้ตรงแทน) |
| ย้ายการ์ด / เปลี่ยนสถานะ (Kanban, Backlog, หน้างาน, Table) | ต้องมี `issue.edit` และเป็นผู้รับผิดชอบ, Reviewer หรือ Tester ของงาน · งานที่ยังไม่มีผู้รับผิดชอบย้ายได้ · Admin ของโปรเจกต์ย้ายได้ทุกงาน · งานของคนอื่นดูได้อย่างเดียว (403 `not_issue_assignee`) · ฟิลด์อื่นยังแก้ได้ตาม `issue.edit` · API ส่ง `canMove` ต่องานให้หน้าเว็บปิดการลาก (ผู้ใช้ตัดสิน 12 พ.ย. 2569) |
| Watch / Unwatch | ทุกคนที่มี `project.view` ทำกับตัวเองได้ |
| View ส่วนตัว, การค้นหาที่บันทึก | เจ้าของเท่านั้น |
| Profile, การแจ้งเตือน, LINE, Session, วันลา | ตัวเองเท่านั้น · Admin ของ Workspace ยกเลิก LINE binding และวันลาของคนอื่นได้ |

## 4. Guest

Guest ใช้ Role ในโปรเจกต์ตามที่ถูกเชิญ (Viewer หรือ Member) แต่**มีเพดาน**ที่ปรับในหน้า L2 ไม่ได้

| เรื่อง | Guest เป็น Viewer (เช่น ลูกค้า, เจ้าของระบบ) | Guest เป็น Member (เช่น Dev outsource, freelance) |
|---|---|---|
| หน้าที่เห็น | Overview, Timeline และงานที่แชร์ให้ (`shared_with_guests`) เท่านั้น | ทุกหน้าของโปรเจกต์เหมือน Member |
| ชื่อผู้รับผิดชอบ | ซ่อน (แสดงเป็น "ทีมพัฒนา") | เห็นชื่อคนในโปรเจกต์นี้ |
| Workload, Lead Dashboard, Reports | ไม่เห็น | เห็นของโปรเจกต์นี้ · ไม่เห็น Workload รวมทุกโปรเจกต์ |
| Bug | ไม่เห็น (ไม่นับใน Overview) | เห็นและทำงานได้ |
| สร้าง / แก้งาน, ไฟล์ | ไม่ได้ | ตามตาราง L2 ของ Member |
| Settings, Audit | ไม่เห็น | ไม่เห็น |
| Time log | ไม่เห็น | ตามสิทธิ์ Member |
| คอมเมนต์ | ได้ ในงานที่แชร์ | ได้ |
| รายชื่อคนในองค์กร | ไม่เห็น | ไม่เห็น (เห็นเฉพาะสมาชิกโปรเจกต์ที่อยู่) |
| สร้างโปรเจกต์, เชิญคน | ไม่ได้ | ไม่ได้ แม้ PM จะเปิด `project.invite` ให้ Member |

การซ่อนข้อมูลของ Guest ทำที่ API (ตัดฟิลด์ก่อนตอบ) ไม่ใช่แค่ซ่อนในหน้าจอ

## 5. ลำดับการตรวจสิทธิ์ในแต่ละคำขอ

```text
1. ล็อกอินแล้ว?                          ไม่ → 401
2. เป็นสมาชิก active ของ Workspace นี้?   ไม่ → 404 (ไม่บอกว่ามี Workspace นี้)
3. Workspace ถูกระงับ / ลบ?               ใช่ → 403 หรือ 410
4. ต้องใช้สิทธิ์ระดับ Workspace?          ตรวจตามข้อ 2 → ไม่มี → 403
5. เข้าถึงโปรเจกต์ได้?
   - เป็นสมาชิกโปรเจกต์               → ใช้ Role ในโปรเจกต์
   - โปรเจกต์ visibility = workspace และไม่ใช่ Guest → ถือเป็น Viewer
   - Workspace Owner / Admin         → เห็นชื่อและข้อมูลสรุป แต่เปิดงานไม่ได้
                                       จนกว่าจะกด "เข้าร่วมในฐานะ Admin" (ดูข้อ 6)
   - อื่น ๆ                          → 403 พร้อม requestAccess (M1)
6. คำนวณสิทธิ์ = ค่าเริ่มต้นของ Role ⊕ ค่าที่ปรับใน project_role_permission
7. ใส่เพดานของ Guest (ข้อ 4)
8. โปรเจกต์ Archive?                      ใช่ → เหลือสิทธิ์อ่านอย่างเดียว
9. เรียกด้วย API token?                   สิทธิ์ = สิทธิ์ของผู้สร้าง token ∩ scopes ของ token
10. เป็นทีม Friday (support session)?     read → GET เท่านั้น · write → เทียบเท่า Admin · บันทึก Audit ทุกคำขอ
11. ตรวจกติกาความเป็นเจ้าของ (ข้อ 3.3) และกติกาข้อมูล (01-entities)
```

### แบ่งหน้าที่ระหว่างฐานข้อมูลกับ API

| ชั้น | ตรวจอะไร |
|---|---|
| **PostgreSQL RLS** | แยก Workspace (`workspace_id = app.workspace_id`) และกันไม่ให้อ่านโปรเจกต์ที่ไม่มีสิทธิ์เข้าถึง (ข้อ 5 ในลำดับด้านบน) · เป็นด่านสุดท้ายถ้าโค้ด API พลาด |
| **NestJS Guard** | ข้อ 1–10 · ใช้ decorator ต่อ endpoint เช่น `@Require('issue.edit')` |
| **Service** | ข้อ 11 เช่น อนุมัติคำขอของตัวเองไม่ได้, เลื่อน Due ต้องมีสิทธิ์ |
| **Serializer** | ตัดฟิลด์ตามเพดานของ Guest |

ผลการคำนวณสิทธิ์ของผู้ใช้ต่อโปรเจกต์เก็บใน Valkey (หมดอายุ 5 นาที) และล้างทันทีเมื่อ Role หรือตาราง L2 เปลี่ยน · หน้าเว็บดึงชุดสิทธิ์ของตัวเองจาก `GET p/my-permissions` เพื่อซ่อนปุ่มที่ใช้ไม่ได้

## 6. Workspace Owner / Admin กับโปรเจกต์ Private

ตัดสิน 5 พ.ย. 2569

- Owner / Admin ของ Workspace **เห็นชื่อ**โปรเจกต์ Private ทุกอัน (รายการโปรเจกต์ใน Admin Console, ผลค้นหาชื่อโปรเจกต์) พร้อมข้อมูลสรุป: PM, จำนวนสมาชิก, สถานะ, วันที่อัปเดตล่าสุด
- **เปิดงาน, ไฟล์ หรือคอมเมนต์ไม่ได้** จนกว่าจะกด "เข้าร่วมในฐานะ Admin"
- เข้าร่วมแล้ว: เป็น Admin ของโปรเจกต์ · บันทึก Audit log (หมวด perm) · แจ้ง Project Owner และ Admin ของโปรเจกต์ทันที · ชื่อแสดงในรายชื่อสมาชิกตามปกติ ไม่มีการเข้าแบบเงียบ
- ใช้แก้ปัญหาโปรเจกต์กำพร้า เช่น PM ลาออก และให้ Owner ลบหรือโอนโปรเจกต์ได้
- โปรเจกต์ visibility = Workspace ไม่ต้องใช้ขั้นนี้ เพราะทุกคนที่ไม่ใช่ Guest เป็น Viewer อยู่แล้ว

## คำตัดสินด้านสิทธิ์ (5 พ.ย. 2569)

| # | เรื่อง | ข้อสรุป |
|---|---|---|
| 1 | เปลี่ยน Due โดยไม่ต้องขออนุมัติ | ค่าเริ่มต้นปิดสำหรับ Member · **PM เปิดได้รายโปรเจกต์**ที่ L2 › สิทธิ์ของแต่ละ Role |
| 2 | ดึง Due เข้ามาเร็วขึ้น | **ไม่ต้องขออนุมัติ** · ยังบันทึกการแก้ไขแผนและ Activity · เหตุผลไม่บังคับ (ผู้ใช้ขอ 8 พ.ย. 2569: ไม่ต้องเตือน ให้ลง Activity ก็พอ)ถ้ามี Baseline |
| 3 | Owner / Admin กับโปรเจกต์ Private | เห็นชื่อ · เข้าได้เมื่อกด "เข้าร่วมในฐานะ Admin" (ข้อ 6) |
| 4 | Guest ที่เป็น Member ในโปรเจกต์ | **ทำงานได้เหมือน Member** แต่ไม่เห็นรายชื่อคนทั้งองค์กร, สร้างโปรเจกต์และเชิญคนไม่ได้ |
