## ทำอะไร

- หน้า Onboarding checklist: ช่วง 7 / 30 / 90 วัน · KPI (Workspace ใหม่ · ครบ 6 ขั้น · เริ่มใช้จริง · ติดเกิน 3 วัน) · แถบผ่านแต่ละขั้นพร้อมจำนวนที่หลุดและเวลาเฉลี่ย · ข้อสังเกตจากข้อมูล · ตารางลูกค้าที่ติดพร้อมตัวกรอง (ติดเกิน 3 วัน · ทดลองใช้เหลือ ≤ 7 วัน · ยังไม่มีคนติดตาม · ตามขั้น)
- ติดตาม (V5): ลำดับขั้นพร้อมวันที่ · สัญญาณ (คำเชิญค้าง ใช้งานล่าสุด) · ผู้ติดตาม · ข้อความสำเร็จรูป (ใช้ของ O22) · ตัวอย่างอีเมล · ส่งได้ 1 ครั้งต่อ 7 วันต่อ Workspace · ไม่ส่งถึงรายชื่อไม่ส่งอีเมล (O23) · บันทึกภายใน
- การ์ด Onboarding ในแท็บภาพรวมของรายละเอียดลูกค้า (V7)
- ตัวเลขคำนวณทุกคืนจาก `onboarding_progress` + ตารางเดิม (เหตุผล SYSTEM_DB ในคอมเมนต์) · ทีม Friday เห็นเฉพาะตัวเลขและชื่อ Workspace ไม่เห็นเนื้อหางาน
- สิทธิ์: Owner และ Support ใช้งาน · การเงินและผู้ตรวจอ่านอย่างเดียว · วิศวกรไม่เห็น
- **คำขอนอก lane:** ลงทะเบียน module (O01) · เมนู (O10) · การ์ด V7 ใน `apps/ops-web/app/(console)/workspaces/[id]` (O11)

## บันทึกผล

ส่งงาน 12 พ.ย. 2569 · ops-api `src/onboarding` · ops-web `app/(console)/onboarding` · ไม่มี migration

**Endpoint** (`ops/onboarding` · อ่าน: Owner / Support / การเงิน / ผู้ตรวจ · เขียน: Owner / Support · วิศวกร 403)
- `GET ops/onboarding?days=7|30|90` → KPI (Workspace ใหม่ · ทดลอง / Free · ครบ 6 ขั้น % + เวลาเฉลี่ย · เริ่มใช้จริง % นิยามเดียวกับหน้าธุรกิจและกำไร · ติดเกิน 3 วัน + ยังไม่มีคนติดตาม) · funnel (ผ่าน % · หลุดจากขั้นก่อน · วันเฉลี่ยถึงขั้น) · insights (ขั้นที่หลุดมากสุด + % จ่ายเงินของคนที่ผ่าน / ไม่ผ่าน · % ผ่านขั้น LINE / อีเมล) · `stuck` และ `inactive` (ไม่มีใครเข้าเกิน 14 วัน)
- `GET ops/onboarding/workspaces/{id}` → ขั้นพร้อมวันที่และ meta · ขั้นที่ติด / วัน · สัญญาณ (คำเชิญค้าง ตอบรับแล้ว ใช้งาน 7 วัน วันที่มีคนเข้า ที่มา Ticket ที่เปิด) · Owner (อีเมลตามสิทธิ์ · อยู่ในรายชื่อไม่ส่งหรือไม่) · การติดตาม · ผู้ติดตามที่เลือกได้ (Owner / Support ที่ active)
- `PUT .../followup { assigneeId?, status?, note? }` ("บันทึกอย่างเดียว") · ลง Audit ของทีมเท่านั้น เพราะบันทึกภายในห้ามไปอยู่ใน Audit log ที่ลูกค้าเห็น
- `POST .../email { subject, body, cannedId?, assigneeId?, note? }` → แทนตัวแปร `{ชื่อ Workspace}` `{ชื่อผู้แจ้ง}` (ชื่อ Owner) · 1 ครั้งต่อ 7 วัน (409 `email_too_soon` · ล็อกแถวในธุรกรรม) · Owner อยู่ในรายชื่อไม่ส่ง = 422 `email_suppressed` · เข้าคิวผ่านแจ้งเตือน + `notification_deliveries` (ท่อเดียวกับประกาศ O24 · API ลูกค้าส่งและอยู่ในประวัติการส่ง O23) · นับยอดใช้ข้อความสำเร็จรูป (O22) · Audit ทั้งของลูกค้าและทีม · ยังไม่มีผู้ติดตาม = ผู้ส่งเป็นผู้ติดตาม

**หน้าเว็บ:** บอร์ด 18 (ช่วง 7 / 30 / 90 วัน · KPI · แถบผ่านแต่ละขั้น ขั้นที่หลุดมากสุดเป็นสีแดง · ข้อสังเกต · ตารางลูกค้าที่ติดพร้อมตัวกรอง ติดเกิน 3 วัน / ทดลองเหลือ ≤ 7 วัน / ยังไม่มีคนติดตาม / ขั้นที่มีคนติดมากสุด / ทั้งหมด / หยุดใช้ · ส่งออก CSV ฝั่งเว็บ) · V5 Drawer (ความคืบหน้า สัญญาณ ผู้ติดตาม ข้อความสำเร็จรูปของ O22 เรียง tag `onboarding` ก่อน · หัวข้อ / ข้อความแก้ได้ · ตัวอย่างอีเมลแทนตัวแปร · บันทึกภายใน · สถานะ · ปุ่มส่งปิดเมื่อส่งไม่ได้) · V7 การ์ดใต้คะแนนสุขภาพ (เฉพาะ Workspace ที่ยังไม่ครบ · แถบ 6 ช่อง · ติดที่ขั้นไหนกี่วัน · ผู้ติดตาม · ปุ่มติดตามเฉพาะ Owner / Support) · การเงิน / ผู้ตรวจไม่เห็นปุ่มติดตาม · วิศวกรไม่เห็นเมนูและได้หน้าไม่มีสิทธิ์

**ต่างจากข้อความงาน / คำตัดสิน**
- ไม่ทำ V6 (แก้ขั้นตอน) และไม่มีปุ่ม "แก้ขั้นตอน" ตามคำตัดสิน · ขั้นแก้ใน `apps/api/src/onboarding/steps.ts` (รหัสขั้นใน ops-api `STEPS` ต้องตรงกัน)
- "คำนวณทุกคืน": งาน `onboarding.reconcile` ของ A43 (01:30) บันทึกขั้นที่ไม่มีเหตุการณ์ลง `onboarding_progress` · หน้านี้คำนวณตัวเลขสดจาก `onboarding_progress` + ตารางเดิมทุกครั้งที่เปิดผ่าน OPS_DB (friday_worker · เหตุผลในคอมเมนต์) ไม่ต้องมีตารางพักผล
- อีเมลช่วยเหลือใช้ event `ops.announcement` (payload `kind: onboarding_followup`) เพื่อไม่ต้องแก้ท่อส่งของ API ลูกค้า · หัวอีเมลจึงขึ้นว่า "ประกาศจากทีม Friday" · ถ้าต้องการหัวเฉพาะให้เพิ่มแบบข้อความใน `apps/api/src/channels/message.ts` ภายหลัง
- เมนูเปิดให้การเงินและผู้ตรวจด้วย (อ่านอย่างเดียว) ตามสิทธิ์ในงาน (เดิม nav กำหนดเฉพาะ Owner / Support)
- ข้อสังเกต "ลูกค้าที่ผูก LINE ยกเลิกน้อยกว่า 2.4 เท่า" ไม่คำนวณในหน้านี้ · แสดง % ผ่านขั้นและชี้ไปหน้าการใช้ฟีเจอร์แทน (ไม่ใส่ตัวเลขที่ไม่ได้คำนวณจริง)
- ตรวจหน้าตาที่ 1440 px ด้วย ops-web dev + ops-api จำลอง (ข้อมูลสมมติ) เทียบกับบอร์ด 18 · ที่ 390 px ตารางเลื่อนแนวนอนและแถบผ่านแต่ละขั้นเรียงเป็นแถว (Drawer V5 ตรวจด้วย component test) · ตรวจจริงผ่าน http://localhost:4000 ตอน deploy Docker
