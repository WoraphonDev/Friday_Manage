## ทำอะไร

- `packages/db/src/credit.ts`: `applyCredit(tx, invoice)` ใช้ในธุรกรรมเดียวกับการสร้างใบแจ้งหนี้ทุกทาง (ลูกค้าซื้อเอง, ทีมออก, ใบเพิ่มหนี้, ใบต่ออายุในอนาคต) · เขียน `workspace_credits` source `applied` (ติดลบ, ผูก invoice_id) · `invoices.credit_applied` · `amount_due` หักเครดิตแล้ว · เครดิตพอทั้งใบ → ชำระแล้วทันที ออกใบกำกับภาษีวันนั้น
- เครดิตไม่ใช่ส่วนลด: subtotal / VAT ไม่เปลี่ยน · ใบกำกับภาษีมีบรรทัด "ชำระด้วยเครดิต" ในส่วนวิธีชำระ (R4)
- ใบที่หักเครดิตถูกยกเลิก → คืนเครดิตเป็นแถว `reversal`
- C4 อัปเกรดกลางรอบ: บรรทัด "ชำระด้วยเครดิต" และยอดที่ต้องชำระจริง (R2) · ส่วนต่างติดลบ: ออกใบลดหนี้ส่วนที่ยังไม่ได้ใช้ แล้วเลือก "เข้าเครดิต" (ค่าเริ่มต้น) หรือ "คืนเงิน" (เกิน ฿10,000 ขออนุมัติ) (R3)
- แท็บการเงินของลูกค้าใน Ops: บัญชีเครดิต (ประวัติ, ลิงก์เอกสารต้นทาง, CSV) + สรุปใบถัดไป · "คืนเป็นเงิน" → ขั้นตอนคืนเงินเดิม (แถว `refunded`) (R1)
- ลูกค้า: การ์ดเครดิตคงเหลือ + ใบถัดไปในหน้า Billing · อัปเกรดเองคิดส่วนต่างตามวันที่เหลือ + หักส่วนที่จ่ายแล้ว + หักเครดิต → ไปหน้าชำระใบแจ้งหนี้เดิม (R5) · ลดแพ็กเกจเองมีผลรอบถัดไป (pendingPlanId) ตรวจขีดจำกัดล่วงหน้า วันที่มีผลยังเกิน → คงแพ็กเกจเดิม 1 รอบ + อีเมล Owner (R6) · แถบการเปลี่ยนที่รออยู่ + ยกเลิกได้ (R7)
- ย้ายสูตรส่วนต่างไปที่ใช้ร่วมระหว่าง ops-api และ API ลูกค้า
