## ทำอะไร

- คำขอ PDPA: บันทึกคำขอที่มาทางอีเมล, นับ 30 วัน, ดำเนินการตามขั้น, ปฏิเสธพร้อมเหตุผลตามกฎหมาย, ลบตามคำขอ (ต้องมีคนที่สองเสมอ · ช่วง Owner คนเดียวให้รอ)
- เหตุละเมิดข้อมูล: บันทึกและนับ 72 ชม. · ร่างหนังสือแจ้ง สคส.
- เอกสารกฎหมาย: สร้างเวอร์ชัน, ต้องยอมรับใหม่หรือแจ้งให้ทราบ, ตั้งเวลาเผยแพร่, รายชื่อผู้ยอมรับ

**ส่งงาน 2026-11-09** · test `privacy-legal.e2e.test.ts` 12 ข้อ · ops-api ทั้งชุด 90 ผ่าน (1 ข้าม = ส่วนที่ต้องใช้ Valkey) · `packages/db` 138 ผ่าน · `pnpm typecheck` ที่รากผ่าน

**Endpoint**
- **คำขอ PDPA**:
  - `GET ops/privacy/requests?status` และ `GET ops/privacy/requests/:id` (ขั้นตอน, ประวัติ, ขอบเขต และแผนการลบ: สิ่งที่ลบ / ทำให้ระบุตัวไม่ได้ / เก็บต่อตามกฎหมาย)
  - `POST ops/privacy/requests` (A3) และ `POST ops/privacy/requests/:id/{verify|advance|reject|erase}` (A5, A6)
- `GET ops/privacy/pending-deletes`: Workspace ที่รอลบ
- **เหตุละเมิด**:
  - `GET|POST ops/privacy/breaches` (A4), `GET|PATCH ops/privacy/breaches/:id`
  - `POST ops/privacy/breaches/:id/{pdpc-notified|subjects-notified|close}` และ `GET ops/privacy/breaches/:id/pdpc-draft`
- **เอกสารกฎหมาย**:
  - `GET ops/legal/documents` (ฉบับที่ใช้ / ตั้งเวลา / ประวัติ / จำนวนผู้ยอมรับ) และ `GET ops/legal/documents/:id` (มีฉบับก่อนหน้าให้เทียบ)
  - `POST ops/legal/documents` (A7) และ `DELETE ops/legal/documents/:id` (ยกเลิกฉบับที่ยังไม่มีผล)
  - `GET ops/legal/acceptances?q&docType&version` และ `/export` (CSV)

**สิทธิ์**

| ส่วน | ทำได้ | อ่านอย่างเดียว | หมายเหตุ |
|---|---|---|---|
| คำขอ PDPA | Owner / Support | ผู้ตรวจ | สั่งลบต้องแตะ key ซ้ำ |
| เหตุละเมิด | Owner / วิศวกร | ผู้ตรวจ | แจ้ง สคส. / แจ้งลูกค้า / ปิดเหตุเป็นงานของ Owner |
| เอกสารกฎหมาย | Owner (แตะ key ซ้ำ) | ผู้ตรวจ | |

**คำตัดสินที่เลือกเอง**
- **ขั้นตอนคำขอ** 5 ขั้น: รับ → ยืนยันตัวตน → ตรวจขอบเขต → ดำเนินการ → แจ้งผล
  - ข้ามการยืนยันตัวตนไม่ได้
  - คำขอลบต้องผ่าน "ลบตามคำขอ" ซึ่งต้องมีคนที่สองอนุมัติเสมอ (`privacy.erase` อยู่ใน `NO_SELF_APPROVAL` อยู่แล้ว · ช่วงมี Owner คนเดียว ถ้า Owner เป็นคนขอต้องรอ) · Support เป็นคนขอแล้ว Owner อนุมัติได้
  - ประวัติทุกขั้นอยู่ใน `staff_audit_logs` (แก้ไม่ได้)
- **การลบ** ทำแบบเดียวกับ API ลูกค้า (`DataRequestsService.anonymizeIfOrphan`):
  - ถอนผู้ขอจาก Workspace ในขอบเขต (ทีม / โปรเจกต์ / ผู้ติดตาม / แจ้งเตือน)
  - ไม่เหลือ Workspace ที่ใช้งาน → ทำบัญชีให้ระบุตัวไม่ได้ และลบ session / identity / 2FA / ลิงก์ / การผูก LINE / ข้อมูลที่มาของการสมัคร
  - งานและคอมเมนต์ยังอยู่ · ใบกำกับภาษีเก็บต่อ
  - Owner คนเดียวของ Workspace ลบไม่ได้จนกว่าจะโอนความเป็นเจ้าของ
- **ไม่มีบัญชีกับ Friday** → คืน `forwardToOwner: true` (น่าจะเป็นข้อมูลที่ Workspace ของลูกค้าเป็นผู้ควบคุม)
- **คำขอดู / สำเนาข้อมูล** ขั้นที่ 4 ทีมแนบไฟล์เอง · ยังไม่สร้างไฟล์ส่งออกจากหลังบ้าน (API ลูกค้ามี `buildSubjectBundle` ต่อ Workspace)
- **เหตุละเมิด**:
  - นับ 72 ชม. จาก `discovered_at` · ความเสี่ยงต่ำไม่ต้องแจ้ง สคส.
  - ปิดเหตุได้เมื่อมีผลประเมินแล้ว และถ้าความเสี่ยงไม่ต่ำต้องแจ้ง สคส. ก่อน
  - ร่างหนังสือแจ้ง สคส. เป็นข้อความตามหัวข้อที่ต้องแจ้ง · ถ้าเกิน 72 ชม. จะใส่ช่องให้เขียนเหตุผลที่ล่าช้า
- **เอกสารกฎหมาย**:
  - เปลี่ยนสาระสำคัญต้องมีผลหลังวันนี้อย่างน้อย 30 วัน · แจ้งให้ทราบมีผลทันทีได้
  - เวอร์ชันต้องใหม่กว่าฉบับล่าสุด · ฉบับที่มีผลแล้วแก้หรือลบไม่ได้
  - "ตั้งเวลาเผยแพร่" = ตั้ง `effective_at` ในอนาคต (API ลูกค้าแสดงเฉพาะฉบับที่มีผลแล้วอยู่แล้ว)

**ยังไม่ทำ**
- Legal hold และนโยบายการเก็บข้อมูลแบบตั้งค่าได้ (ยังไม่มีตาราง)
- ปุ่ม "ลบจริง" ของ Workspace ที่รอลบ (ระบบลบเองเมื่อครบ 30 วันอยู่ที่ API ลูกค้า)
- ส่งอีเมลแจ้งเอกสารใหม่ล่วงหน้าถึงผู้ใช้ทุกคน

**คำขอนอก lane**
- API ลูกค้าต้องแยก `requires_acceptance`: แบนเนอร์ "ข้อกำหนดเปลี่ยน" บังคับกดยอมรับเฉพาะฉบับที่ `true` · `false` แสดงแบนเนอร์ 14 วัน
