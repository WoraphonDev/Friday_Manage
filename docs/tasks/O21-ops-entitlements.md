## ทำอะไร

- ตารางฟีเจอร์ / ขีดจำกัด × แพ็กเกจ แก้ได้โดยไม่แก้โค้ด · บันทึกเป็นเวอร์ชันใหม่ (P2) พร้อมจำนวนลูกค้าที่ถูกลดสิทธิ์ก่อนบันทึก · ประวัติ (P3)
- ปรับเฉพาะราย (override): ที่นั่ง พื้นที่ไฟล์ API ต่อนาที Automation ต่อเดือน SSO · ต้องมีเหตุผลและวันหมดอายุ (ยกเว้นสัญญา Enterprise) · เกินแพ็กเกจ 20% ต้องให้ Owner อนุมัติ · เตือนล่วงหน้า 7 วันก่อนหมด
- `plan-limits.ts` ของ API อ่านเวอร์ชัน + override แทนค่าคงที่ (402 เหมือนเดิม)
- รวม Rate limit ต่อลูกค้า (แผนเฟส 2 ใน ComingSoon) เป็นขีดจำกัด "API ต่อนาที"

API ลูกค้า (`core/plan-limits.ts`)
- ที่นั่ง โปรเจกต์ พื้นที่ อ่านจากเวอร์ชัน + override (402 `plan_limit_reached` เหมือนเดิม) · `GET w/usage` มี `entitlements` (เวอร์ชัน, ค่าทุกคีย์, คีย์ที่อยู่ในช่วงผ่อนผัน)
- ฟีเจอร์ที่บังคับแล้ว → 402 `plan_feature_unavailable` (`details.kind = feature`): Automation (สร้างกฎ + engine ข้ามเมื่อไม่มีฟีเจอร์), API token (สร้าง + ทุกคำขอ Bearer), LINE OA / Webhook (ตั้งค่า), Import โหมดอัปเดต, เชิญ Guest (คำเชิญ + ลิงก์เชิญ) · หน้าเว็บลูกค้าแสดงข้อความของ API ผ่าน Dialog Q2 แบบทั่วไป
- Automation ต่อเดือน: ครบโควตา engine บันทึกเป็น `skipped` (`plan_quota_reached`) ไม่นับ run ที่ข้าม
- API ต่อนาที (รวม Rate limit ต่อลูกค้าจาก ComingSoon): คำขอ Bearer เกิน → 429 `rate_limited` + `Retry-After` · ตอบ `X-RateLimit-Limit / Remaining` · นับในหน่วยความจำของ process (API รันตัวเดียว) · หลายเครื่องต้องย้ายไป Valkey · ทาง Bearer อ่านสิทธิ์ที่เก็บไว้ไม่เกิน 10 วินาที ทางเขียนอื่นอ่านสดเสมอ
