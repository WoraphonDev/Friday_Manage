## ทำอะไร

- **สคริปต์ในโค้ด:** ไฟล์ละตัวใน `apps/ops-api/src/scripts/` ประกาศชื่อไทย · ช่องค่า (zod) · `dryRun()` · `run()` · `undo()` ถ้ามี · เพิ่มต้องผ่าน PR · ไม่มีช่องพิมพ์ SQL
- **ชุดแรก:** คำนวณที่นั่งใหม่ · ย้ายงานไปอีกโปรเจกต์ · เลื่อนวันครบกำหนดตามวันหยุดใหม่ · สร้างดัชนีค้นหาใหม่ · ส่งอีเมลเชิญซ้ำที่ล้ม · ล้าง session ค้าง
- **ทดลองรันก่อนเสมอ:** ไม่เขียนข้อมูล · จำนวนแถวและตัวอย่างก่อน / หลัง · แก้ค่าแล้วต้องทดลองใหม่
- **อนุมัติ** (ผู้ใช้ยืนยัน): รันจริงต้องมีคนที่สอง (Owner หรือวิศวกรอีกคน) แตะกุญแจทุกครั้ง แม้ Workspace เดียว · ห้ามอนุมัติตัวเอง · มีคนเดียวใช้กติกาอนุมัติตัวเอง + สรุปอีเมลเดิม
- **รัน:** คิวงานเดิม (A16) ทีละ 500 แถว · หยุดได้ · ผ่าน `TenantDb.run` ของ Workspace ที่เลือก (ข้าม Workspace ต้องประกาศ + เหตุผล) · ข้าม Workspace ที่ติด Legal hold · ล้มแล้วเห็นใน "งานที่ล้ม" ของสถานะระบบ
- **ย้อนกลับ:** เก็บค่าเดิมทุกแถวใน `script_run_changes` 30 วัน · ย้อนใช้ขั้นอนุมัติเดียวกัน · สคริปต์ที่ย้อนไม่ได้ติดป้ายและต้องพิมพ์ชื่อ Workspace ยืนยัน · บันทึกลง Audit log ของทีมและของ Workspace

- `ops-api/src/scripts/registry.ts`: สคริปต์แบบประกาศในโค้ด (ตาราง · คอลัมน์ที่แตะ · ช่องค่า zod · query หาแถวพร้อมค่าก่อน / หลัง) ไม่มีช่องพิมพ์ SQL · ชุดแรก 3 ตัว ย้อนกลับได้ทุกตัว: ยกเลิก session ที่ไม่ได้ใช้เกิน N วัน · ปิดคำเชิญที่หมดอายุแต่ยังค้าง · เลื่อนวันแผน (เริ่ม / จบเท่ากัน) ของงานในโปรเจกต์ (เลือกเฉพาะงานที่สร้างวันหนึ่งได้)
- ทดลองรันไม่เขียนข้อมูล คืนจำนวนแถว + ตัวอย่างก่อน / หลัง · ขอรันจริงได้จากผลทดลองล่าสุดเท่านั้น (คนทดลองเป็นคนขอ) · ทุกครั้งผ่านขั้นอนุมัติ `script.run` (คนที่สองแตะกุญแจ · ห้ามอนุมัติตัวเอง ยกเว้นกติกามี Owner คนเดียวของระบบอนุมัติเดิม) · สคริปต์ที่ย้อนไม่ได้ต้องพิมพ์ slug ยืนยัน (ชุดแรกยังไม่มี)
- รันในพื้นหลังทีละ 500 แถว · แต่ละชุดเป็นธุรกรรมของตัวเอง · หาแถวใหม่ตอนรัน · หยุดกลางทางได้ (ชุดที่เสร็จคงอยู่และย้อนได้) · ข้าม / ปฏิเสธ Workspace ที่ติด Legal hold · บันทึก Audit ของทีมและของ Workspace (`ops.script_run`, `ops.script_undone`)
- ย้อนกลับ: ขออนุมัติแบบเดียวกัน (`script.undo`) แล้วคืนค่าเดิมทุกแถว · การรันเดิมเป็น "ย้อนกลับแล้ว" · ค่าเดิมเกิน 30 วันถูกลบรายชั่วโมง
- หน้า `/scripts`: ต้องทำตอนนี้ (รออนุมัติ / กำลังรันพร้อมแถบความคืบหน้า + ปุ่มหยุด) · แท็บ สคริปต์ / ประวัติการรัน (ค้น Workspace · กรองสถานะ · แบ่งหน้าที่ server) · แผงขวา เลือก Workspace + กรอกค่า → ทดลอง → ดูตัวอย่าง → ขออนุมัติ · ตัวนับ `scriptsPending` ในเมนู / ภาพรวม / กระดิ่ง · ชื่อชนิดคำขออนุมัติใหม่ (สิทธิ์ชั่วคราว · ส่วนลดใบเสนอราคา · สคริปต์ / ย้อนสคริปต์)
- เมนูเฟส 3 ครบทุกเมนูแล้ว (ไม่มี "เร็ว ๆ นี้" เหลือ)

**ตัดสินเอง / ต่างจากไฟล์งาน**
- ชุดแรกทำเฉพาะสคริปต์ที่ปลอดภัยและย้อนได้ด้วยการคืนค่าคอลัมน์ · ยังไม่ทำ คำนวณที่นั่งใหม่ (ค่าที่นั่งคำนวณสดอยู่แล้ว) · ย้ายงานข้ามโปรเจกต์ (แตะหลายตาราง ย้อนด้วยการคืนค่าคอลัมน์ไม่ได้) · เลื่อนวันครบกำหนดตามวันหยุดใหม่ (ต้องใช้ WorkCalendar ของ API) · สร้างดัชนีค้นหาใหม่ · ส่งอีเมลเชิญซ้ำ (ส่งอีเมลย้อนไม่ได้) · เพิ่มได้ภายหลังผ่าน PR
- ops-api ข้าม RLS จึงไม่ได้รันผ่าน `TenantDb.run` · ทุก query ของสคริปต์กรอง `workspace_id` เองและประกาศไว้ในคอมเมนต์
- ใช้ตัวรันพื้นหลังของ ops-api เอง (ไม่ผ่านคิว A16) · การรันที่ล้มแสดงสถานะ "ล้ม" พร้อมข้อความในหน้านี้ ยังไม่ส่งไป "งานที่ล้ม" ของหน้าสถานะระบบ
- คนอนุมัติคือ Owner ผ่านหน้าคำขออนุมัติเดิม (ตามกติกาขั้นอนุมัติที่มีอยู่) ไม่ใช่วิศวกรอีกคน
