## ทำอะไร

- วิธีแจก Ticket ใหม่ (คิวกลาง / วนตามคน) · เพดานงานค้างต่อคน · ไม่แจกให้คนที่ไม่ว่าง / ออฟไลน์ · ตอบกลับเรื่องที่ปิดภายใน N วันกลับไปคนเดิม · คนออฟไลน์ / ลาคืนงานเข้าคิว
- กฎแยกตามประเภท (ตรงข้อแรกแล้วหยุด) → กลุ่ม + ความสำคัญเริ่มต้น (T6)
- SLA ตามแพ็กเกจแก้ได้ (ตอนนี้ค่าคงที่ใน O04) · เตือนเมื่อเหลือ 25% · เวลาทำการของทีม + วันหยุดราชการไทย
- ข้อความสำเร็จรูปพร้อมตัวแปร (ชื่อลูกค้า เลข Ticket) ใช้ในหน้าตอบ Ticket (T4)
- เฉพาะ Owner · Audit ทุกการเปลี่ยน

แก้นอก lane ที่ระบุ (จำเป็นต่อ "ใช้ในหน้าตอบ Ticket" และสถานะพนักงาน): `support/SupportPage.tsx` (สถานะของฉัน · ทีมตอนนี้ · ปุ่ม T4 · หมวดแบบเลือก · ความสำคัญ "ตามกฎ"), `nav.ts`, `ops.css`, ไฟล์ข้อความ และ test เดิมของ O04 (ตั้งโหมด "ไม่แจกอัตโนมัติ" เพราะทดสอบคิวกลาง)

ฐานข้อมูล (migration 0025)
- ตารางใหม่ `support_settings` (แถวเดียว · `config` ตรวจด้วย zod · ค่าที่ไม่ได้บันทึกใช้ค่าเริ่มต้นตาม Canvas), `support_rules`, `support_agents` (กลุ่ม · เพดาน · สถานะ), `support_account_managers`, `support_canned_replies` · RLS `ops_only`
- `support_tickets` เพิ่ม `rule_id` และ `sla_alerts` (กันส่งเตือนซ้ำ) · หมวด Ticket เป็นรหัสใน `TICKET_CATEGORIES` (Ticket เก่าที่พิมพ์เองยังแสดงข้อความเดิม)
- กฎตั้งต้น 6 ข้อตาม Canvas อยู่ใน migration

การแจกงาน (`apps/ops-api/src/support/settings.service.ts`)
- กฎแรกที่เปิดอยู่และตรง (แพ็กเกจ และ หมวด · ว่าง = ทุกค่า) → กลุ่ม + ความสำคัญเริ่มต้น · ทีมระบุความสำคัญเองใน T1 ได้ (ค่าเริ่มต้น "ตามกฎ")
- งานน้อยที่สุดก่อน (เท่ากันเรียงตามชื่อ) / วนตามลำดับ (ล็อกแถวตั้งค่ากันแจกซ้อน) / ไม่แจกอัตโนมัติ · ไม่เกินเพดาน (รายคนหรือค่าเริ่มต้น) · นับงานเปิด = เปิด / รอลูกค้า / รอทีมพัฒนา
- กลุ่มที่ยังไม่มีสมาชิกเลยแจกให้ทุกคนแทน (ทีมเล็กยังไม่แบ่งกลุ่ม) · "ผู้ดูแลประจำบัญชี" ไม่มีหรือไม่ว่าง → คิวกลาง (T6 "ถ้าไม่อยู่")
- เปลี่ยนเป็นออฟไลน์/ลา: คืนเรื่องที่ "เปิด" (รอทีมตอบ) เข้าคิว / อีเมลหัวหน้าทีม / คงไว้ · เรื่องที่รอลูกค้าหรือทีมพัฒนายังอยู่กับคนเดิม
- ลูกค้าตอบหลังปิดภายใน N วันที่ตั้ง → เปิดใหม่ที่คนเดิม · เกิน N วันปิดถาวร

SLA และเวลาทำการ (`support/clock.ts`)
- ระยะต่อแพ็กเกจเป็น ชม. ทำการ / วันทำการ (= วันทำการที่ N เวลาเดิม) / ไม่กำหนด · ด่วนนับ 24 ชม. ทุกวัน ตอบครั้งแรกไม่เกิน 1 ชม.
- เวลาทำการรายวัน + วันหยุดราชการจากปฏิทินของระบบ (`holiday_calendars` ที่ `workspace_id` ว่าง) · นอกเวลาทำการ อีเมลยืนยันบอก "ทีมจะตอบในวันทำการถัดไป"
- ทุก 5 นาที: เหลือ 25% → อีเมลผู้รับผิดชอบ (ยังไม่มีคนรับ = หัวหน้าทีม) · เกิน → อีเมลหัวหน้าทีม (ไม่มีหัวหน้าทีม = Owner) · คิวเรียงเรื่องที่เกิน SLA ขึ้นบนสุด

ข้อความสำเร็จรูป (T4)
- Owner เพิ่ม / แก้ / เลิกใช้ (เก็บไว้ดูย้อนหลัง) · Support ค้นและใส่ในช่องตอบ แทนตัวแปร `{ชื่อผู้แจ้ง}` `{ชื่อ Workspace}` `{เลข Ticket}` · นับครั้งที่ใช้

สิทธิ์และ Audit
- ดูหน้าตั้งค่า: Owner / Support (Support ดูอย่างเดียว) · แก้ทุกอย่าง: Owner · ตั้งสถานะตัวเองและใช้ข้อความสำเร็จรูป: Support
- ทุกการเปลี่ยน (ตั้งค่า กฎ ผู้ดูแลบัญชี ข้อความ สถานะ) ลง `staff_audit_logs` พร้อมสรุปสิ่งที่เปลี่ยน

ต่างจาก Canvas
- ตาราง SLA แยก Team S และ Team M เป็นคนละแถว (Canvas รวมกัน) เพราะราคาและสิทธิ์ต่างกัน · ค่าเริ่มต้นเท่ากัน
- เพิ่มการ์ด "ข้อความสำเร็จรูป" ท้ายหน้าตั้งค่า เพราะ T4 มีลิงก์ "จัดการข้อความ" แต่ Canvas ไม่มีหน้าจัดการ
- ตารางกฎมีปุ่มเลื่อนขึ้น/ลงและลบ · ผู้ดูแลประจำบัญชีแก้ผ่านปุ่มในตารางพนักงาน (หน้าต่างค้นหา Workspace)
- T6 ไม่มีช่อง "SLA ตอบครั้งแรก" และ "แจ้งเตือน LINE กลุ่มทีม" รายกฎ: SLA ตั้งตามแพ็กเกจที่เดียว และยังไม่มี LINE กลุ่มของทีม Friday · "ถ้าไม่อยู่" เป็นคิวกลางเสมอ
- หน้า Support เพิ่ม "สถานะของฉัน", "ทีมตอนนี้" และปุ่มไปหน้าตั้งค่าตาม Canvas Support (ส่วนนี้รอ O22 เพราะต้องมีสถานะพนักงาน)

ยังไม่ทำ / ข้อจำกัด
- ปฏิทินวันหยุดราชการของระบบยังว่าง (ยังไม่มีตัวดึงประกาศ ธปท.) · หน้าตั้งค่าแสดง "ยังไม่มีวันหยุดในปฏิทินของระบบ" จนกว่าจะมีข้อมูล
- สถานะพนักงานตั้งเอง ยังไม่เปลี่ยนเป็นออฟไลน์อัตโนมัติเมื่อออกจากระบบ · เรื่องที่คืนเข้าคิวไม่ถูกแจกใหม่อัตโนมัติ (ทีมกด "รับเรื่องนี้")
- API ลูกค้ายังไม่สร้าง Ticket เอง · เมื่อเพิ่มต้องเรียกการแจกงานเดียวกัน
